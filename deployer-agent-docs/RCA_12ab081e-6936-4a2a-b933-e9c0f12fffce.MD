# RCA — Deploy run 12ab081e-6936-4a2a-b933-e9c0f12fffce (readgit-app)

## Symptom
Deploy failed at `deploy_k8s`. The backend container CrashLoopBackOff (early), restarts=3, lastExit=1/Error. Pod logs:

```
ERROR:    Error loading ASGI app. Could not import module "server".
Backend died, shutting down Nginx...
Starting FastAPI backend: uvicorn server:app --host 0.0.0.0 --port 8001 --workers 1  in /app/backend
```

## Root cause — backend stack does not match the deployment template
This deployment uses the `expo_mongo_base_image_eas` template, which is a **Python FastAPI + MongoDB** runtime. Its READONLY supervisor config (`/app/etc/supervisor/conf.d/supervisord.conf`, baked into the base image) starts the backend with:

```
command=/root/.venv/bin/uvicorn server:app --host 0.0.0.0 --port 8001 --workers 1
directory=/app/backend
```

That requires a Python module `server` (i.e. `/app/backend/server.py` exposing `app`).

The actual backend in `/app/backend` is a **Node.js / TypeScript Express application** (`fleet-management-api`), not Python:
- Entry point: `/app/backend/src/index.ts` → `import express ...`, compiled to `dist/index.js`, intended to start via `node dist/index.js` (see `backend/package.json` `start` script and `backend/Dockerfile` `CMD ["node","dist/index.js"]`).
- There is **no `server.py`** anywhere in `/app/backend`, so uvicorn cannot import module `server`, the backend process exits 1, the entrypoint tears down nginx, and the pod crash-loops.
- Datastore is **PostgreSQL via Sequelize** (`backend/.env`: `DATABASE_URL=postgres://fleet:...@localhost:5432/fleet_test`, deps `pg`, `pg-hstore`, `sequelize`). It also uses `socket.io`, `cloudinary`, `nodemailer`.
- `package.json` description is literally "Fleet Management System API - **Railway Deployment**" — the backend was authored for a Node/Postgres host (Railway), not the Emergent Expo+FastAPI+Mongo template.

A leftover generic `backend/requirements.txt` exists but is unused (no `server.py`); it does not make this a Python app.

## Why this is not a manifest fix or a one-line source fix
1. The supervisor backend command (`uvicorn server:app`) comes from the READONLY base-image config and cannot be changed per-app via the manifest set.
2. The pipeline provisions **MongoDB Atlas only**. This app requires **PostgreSQL**, which the Emergent pipeline does not provision — so even if the Node process were started correctly, it has no database to connect to in production.
3. The fix is a re-architecture, not a patch.

## Verification
Reproduced in the eph sandbox against this run's pulled source:
- `/app/backend` contains `src/index.ts`, `package.json` (name `fleet-management-api`, `main: dist/index.js`), `tsconfig.json`, `vitest.config.ts` — no `server.py`.
- Supervisor config runs `uvicorn server:app` in `/app/backend` → matches the production `Could not import module "server"` crash exactly.

## Suggested fix (for E1 / main agent)
The backend must be made compatible with the Emergent `expo_mongo_base_image_eas` template. Options:
- **Port the backend to Python FastAPI + MongoDB**: create `/app/backend/server.py` exposing a FastAPI `app`, with a `/api/*` router and a `/health` endpoint, using `motor`/`pymongo` against the pipeline-provided `MONGO_URL` / `DB_NAME`. Reimplement the Express routes/controllers, auth (JWT), socket, and file-upload logic in FastAPI, and replace the Sequelize/Postgres data layer with MongoDB collections.
- The current Node/TypeScript/Express + PostgreSQL stack cannot be deployed on this template as-is (no Node runtime driving the backend, no Postgres provisioned).

Do not re-trigger the deploy until the backend is a FastAPI `server:app` on Mongo — a rebuild on the current source crash-loops identically.
