# RCA — run 86fe70e8-5ab8-4b75-a01a-5db314fbfd82 (readgit-app)

## Symptom
Deploy failed at `deploy_k8s`: the backend container crash-loops (CrashLoopBackOff, restarts=3, exit 1). Rollout logs repeat:

```
Starting FastAPI backend: uvicorn server:app --host 0.0.0.0 --port 8001 --workers 1  in /app/backend
ERROR:    Error loading ASGI app. Could not import module "server".
Backend died, shutting down Nginx...
nginx: connect() failed (111: Connection refused) ... GET /health ... upstream http://127.0.0.1:8001/health
```

Backend never binds :8001 → nginx `/health` gets connection-refused → pod never becomes ready → `deploy_k8s` fails (not retryable). (Same failure on the prior run 12ab081e.)

## Root cause — backend stack does not match the deployment template
The deployment template is `expo_mongo_base_image_eas`, which deploys a **Python FastAPI + MongoDB** backend. The platform launches the backend via the read-only supervisor config:

```
[program:backend]
command=/root/.venv/bin/uvicorn server:app --host 0.0.0.0 --port 8001 ...
directory=/app/backend
[program:mongodb]
command=/usr/bin/mongod ...
```

But the actual code in `/app/backend` is a **Node.js / TypeScript Express app** (`fleet-management-api`), not Python:
- No `server.py` exists → `uvicorn server:app` → `Could not import module "server"`. (`requirements.txt` is present but is unused scaffolding — there is no FastAPI app.)
- Entry point is `src/index.ts` → `dist/index.js` (`node dist/index.js`); deps are `express`, `socket.io`, `sequelize`, `pg` (package.json).
- Database is **Postgres**, not MongoDB: `backend/.env` has `DATABASE_URL=postgres://fleet:...@localhost:5432/fleet_test`, and `src/config/database` uses Sequelize/pg. The platform provisions MongoDB only — there is no Postgres backing store in production.
- The app's own `backend/Dockerfile` (`node:20-alpine`, `CMD ["node","dist/index.js"]`) is NOT used by the deploy pipeline; the platform's Python-based image + supervisor command are.

## Why this is not a manifest fix
The supervisor backend command (`uvicorn server:app`) and `mongod` are platform-managed read-only files, and the production runtime image is Python-based (venv at `/root/.venv`) with no Node runtime. Even if the image were rebuilt to run Node, the pipeline provisions MongoDB — the app's Sequelize/Postgres layer has no database in production. A manifest edit cannot reconcile this; it would rebuild and fail identically. No manifest change was made.

## Fix (Source / E1)
The backend must be reimplemented to match the Emergent-supported stack for this template:
1. Provide a Python FastAPI app at `/app/backend/server.py` exposing an ASGI `app` object (routes under `/api/*`), with deps in `requirements.txt`.
2. Use **MongoDB** via the injected `MONGO_URL` / `DB_NAME` (e.g. `motor`) instead of Postgres/Sequelize. Migrate the fleet-management data model (users, drivers, trips, stops, etc.) from Postgres tables to Mongo collections.
3. Remove reliance on `DATABASE_URL`/Postgres; the platform does not provision Postgres for this template.

This is a full backend port (Node/Express/Postgres → Python/FastAPI/MongoDB), not a small file edit. Reproduced in the eph sandbox: `/app/scratch/backend` has no `server.py` and is a Node/TS project — confirming the exact import failure seen in the rollout logs.

## Alternative
If a Node + Postgres backend is a hard requirement, this app is not deployable on the `expo_mongo_base_image_eas` template as-is — that is a platform/stack-support limitation and needs platform-side support, not a code tweak.
